# 简历字条 · 语言规则（抽象版）

> 本文件只有规则，不含任何真实简历内容。示例均为虚构。
> 生成时以 `src/resume_system/prompts/b_style.md` 为准，本文件供人阅读和校准。

## 一、每条字条的结构

`**能力短语**：描述句`

- 能力短语：两个名词「A与B」，抽象到能力层，不复述事项
- 描述句：无主语、动词开头，「、」连动作，「；」分阶段（前半做什么，后半产出什么）

## 二、力度词（每条 1–2 处）

- 个人贡献词：独立负责 / 主导 / 统筹 / 主动牵头 / 负责
- 执行力度词：主动 / 深入 / 高效 / 精准 / 成功 / 自动化 / 系统性 / 持续 / 逐项
- 团队协作不写“独立”；不每个动词都加

## 三、工具与方法

用「运用 / 使用 / 结合 / 经…」把工具嵌进动作，不单独罗列“掌握 / 熟练”。

反例：熟练使用 Excel 进行数据汇总。
正例：使用 Excel 维护 400 余条报名记录，逐项核对重复与缺失信息。

## 四、数字与结果：结果 > 规模 > 过程

1. **结果/成效**（按行业选）：销售额、转化率、留存、成本下降、效率提升、错误率下降、准确率、排名/获奖等级、论文/专利、上线/采纳
2. **规模**：用户数、订单数、SKU、场次、人数、覆盖城市、样本量
3. **过程**：负责、参与、跟进

有结果就不写过程；只有过程就如实写过程，不编数字。模糊数用「约」「以上」。

## 五、价值收尾（5 类）

1. 实现…（关键突破 / 经验可复用 / 完整闭环）
2. 以数据支撑…决策
3. 为…提供依据 / 提供支持
4. 保障…（准确可追溯 / 稳定供给）
5. 体现…能力 / 具备…能力

高贡献条目必须落价值；低贡献条目允许弱收尾，但不要停在“获奖/完成”。

## 六、加粗

`desc` 是纯文本，要加粗的词放进 `bold` 数组，必须原样出现在文本里；每条 3–5 个，优先贴 JD 命中词、工具、数字、成果词。维度标签由渲染器自动加粗，不用放进 bold。

## 七、硬边界

1. 价值升华必须基于已有证据，不得凭空捏造能力或成果
2. 一条字条一个能力维度，同段经历 2–4 条不重复
3. 角色词与力度词反映真实分工，不夸大
